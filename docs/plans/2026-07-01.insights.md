## 🌟 关键经验提炼

1. **批量 UI 修改识别**：同一 commit 中大量同类变更（如 `text-[10px]` → `text-[11px]`）表明这是**样式系统级调整**，而非单点修复。分析时发现 5+ Vue 组件均被修改，确认了全局风格统一的设计意图。

2. **关注点分离模式**：将菜单端点从 `menus.py` 剥离到独立 `menu.py` 遵循单一职责原则。这是 FastAPI API 路由管理的典型最佳实践——每个模块对应一个明确的功能域。

3. **前后端分离的信号检测**：commit 中有独立的 backend API（menu endpoint 注册）+ frontend preferences + static assets，说明这是一个完整的 full-stack feature launch。检查模式应为：**后端 → 前端 → 文档**。

4. **Tailwind 硬编码的维护风险**：项目中存在大量 `text-[10px]`、`text-[11px]` 等任意值（arbitrary value）写法，虽灵活但容易不一致。建议后续统一用 Tailwind 的 scale（sm/base/lg）或 CSS variables。

5. **UI/Style 变更的高效识别**：通过统计 `git diff --stat` 和搜索 `[0-9]+px` 模式变更，可在数秒内判断一个 commit 是"功能开发"还是"样式微调"。commit 360c119 中 14 个文件变更但核心逻辑改动仅 ~20%，主体为 UI 文字对齐。
