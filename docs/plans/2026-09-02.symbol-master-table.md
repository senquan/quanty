# 方案：backend 自建标的主数据表，修复持仓中文名缺失

- 状态：草稿（待实施）
- 日期：2026-09-02
- 提出背景：量化概览(quant/dashboard)的持仓/成交中文名大量缺失，只显示股票代码。

## 1. 目标

1. backend 自建一张 `instruments`(标的主数据)表，承载 `symbol → name`(及 exchange/board 等)。
2. 任意出现在持仓/成交里的代码都能解析出中文名，不再回退成裸代码。
3. 名字数据源来自 data-cleaner 的只读元数据接口（与 `market_proxy` 取价同一边界：backend 存、dc 供），首次缺失时懒回填并缓存。
4. 不改动模拟撮合服务的"可交易标的范围"(`available-symbols`/`market/quotes` 仍是其内置 5 只演示标的，属另一关注点)。

## 2. 现状证据（带文件行号）

- 前端名字映射只由 `getAvailableSymbolsApi()` 构建，源是后端写死的 5 只：
  - `frontend/apps/web-ele/src/views/quant/dashboard/index.vue:159-161`
  - `backend/app/services/huatai_trading.py:386-394`（`get_available_symbols` 返回贵州茅台/上证指数/宁德时代/招商银行/格力电器 5 只）
- 名字缺失回退逻辑：`index.vue:116`（`name: symbolNameMap.value[p.symbol] || p.symbol`）与 `index.vue:134`（成交行同款）。
- 持仓/成交代码来源：调仓链路 `proxy.scores` → dc `POST /strategy/scores` → `engine.compute_target`，目标持仓为任意 A 股代码，且 holdings **不含 name**：
  - `backend/app/services/rebalance_service.py:121,125`（target holdings）
  - `data-cleaner/app/strategy/engine.py:1033-1042`（`holdings:[{symbol,score,weight,industry,z_scores}]`，无 name）
  - `data-cleaner/app/api/v1/strategy.py:161-166`（scores 端点）
- dc 内部有中文名但无 HTTP 出口：`engine.py:555`（`meta_map.get(s).get("name")` 用于 ST 过滤），`industry_store._sync_meta_map()`。
- 建表约定：backend 不用 alembic，`Base.metadata.create_all(tables=[...])` + 进程内 `asyncio.Lock` 幂等建表，见 `backend/app/services/trading_repository.py:28-67`（`ensure_trading_tables`）。

## 3. 架构

```
data-cleaner (只读元数据)                backend (交易中心)
  ┌─────────────────────┐   HTTP        ┌──────────────────────────┐
  │ GET /strategy/       │ ───────────▶  │ GET /trading/symbols/    │
  │     instruments/     │  因子_strategy│     metadata?symbols=     │
  │     metadata?sym=    │   _proxy      │  1) 查 instruments 表     │
  │  返回 {sym:{name,    │              │  2) 缺失→调 dc 元数据      │
  │        exchange}}    │ ◀───────────  │  3) upsert 回填 instruments│
  └─────────────────────┘   HTTP        └──────────────────────────┘
                                                       │
                                              instruments(symbol,name,
                                              exchange,board,updated_at)

前端 dashboard：用 position+trade 的实际代码集合调 /trading/symbols/metadata
               构建 symbolNameMap，替代 getAvailableSymbolsApi。
```

边界说明：dc 新增的 `instruments/metadata` 是**只读**元数据接口（无副作用），符合"data-cleaner 不碰交易、backend 存储"的既定边界；`instruments` 表归 backend 所有，dc 仅作为名字数据源（如同 `market_proxy` 作为价格数据源）。

## 4. 改动清单

### 4.1 data-cleaner：新增只读标的基础信息接口
- `data-cleaner/app/api/v1/strategy.py`：新增 `GET /strategy/instruments/metadata`，参数 `symbols`（逗号分隔，可选；缺省返回全量），从 `industry_store._sync_meta_map()` 取 `name`/`exchange`/`board`（exchange 由 symbol 后缀 `.SH/.SZ/.BJ` 推导），返回 `{symbol: {name, exchange, board}}`。只读、无副作用。
- 校验：`_sync_meta_map` 的字段名（确认含 `name`、是否含 `exchange`/`board`），按需补齐映射。

### 4.2 backend：标的主数据表与仓储
- `backend/app/models/trading.py`：新增 `Instrument` 模型
  - `symbol String(32) PK`、`name String(64)`、`exchange String(8) NULL`、`board String(16) NULL`、`updated_at DateTime`。
- `backend/app/services/trading_repository.py`：
  - `ensure_trading_tables()` 的 `tables=[...]` 列表加入 `Instrument.__table__`，并在建表后幂等 seed 现有 5 只演示标的（`600519.SH/贵州茅台` 等，与 `huatai_trading.get_available_symbols` 对齐）以免演示标的首次加载无名。
  - 新增 `upsert_instruments(session, rows: list[dict])`、`get_instruments(session, symbols: list[str]) -> dict[symbol, Instrument]`、`get_all_instruments(session) -> list[Instrument]`。
  - import 加入 `Instrument`。
- `backend/app/core/database.py` 的 `Base` 已统一，无需改。

### 4.3 backend：proxy 与端点（端点只读主表，回填在行情更新环节）
- `backend/app/services/factor_strategy_proxy.py`：新增 `instrument_metadata(db, symbols: list[str]|None) -> dict`，调 dc `GET /strategy/instruments/metadata`（仅回填时调用）。
- `backend/app/api/api_v1/endpoints/trading.py`：新增 `GET /trading/symbols/metadata`：
  - **只读** backend `instruments` 主表，入参 `symbols`（逗号分隔，可选）过滤。
  - **不触发**任何 dc 查询 / 回填：加载路径零外部依赖、零额外延迟；查不到的代码前端回退成裸代码即可。
  - 用 `Response.success(data=...)`。
- `backend/app/services/portfolio_valuation_service.py`（`run_eod_valuation` 盘后估值 =「更新行情」批量环节）：`_value_one_strategy` 在为持仓 `symbols` 取最新价后，顺带对主表中**缺失**的代码调 `instrument_metadata` 并 `upsert_instruments` 回填。该环节在加载路径之外，dc 不可用时仅告警、不影响估值。

### 4.4 frontend：用实际代码解析名字
- `frontend/apps/web-ele/src/api/core/trading.ts`：新增 `getSymbolMetadataApi(symbols?: string[])`，调 `/trading/symbols/metadata?symbols=`。
- `frontend/apps/web-ele/src/views/quant/dashboard/index.vue`：
  - `load()` 中把 `getAvailableSymbolsApi()` 替换为：先取 positions+trades 的代码集合 → `getSymbolMetadataApi(symbols)` → 构建 `symbolNameMap`（保持 `|| p.symbol` 兜底）。
  - 仅在 `symbolNameMap` 仍缺时回退裸代码（兼容性不变）。

## 5. 分步步骤（每步带 verify）

1. **dc 元数据接口**
   - 改 `data-cleaner/app/api/v1/strategy.py` 加 `GET /strategy/instruments/metadata`。
   - verify：`curl '<dc>/api/v1/strategy/instruments/metadata?symbols=600519.SH,300750.SZ'` 返回含 name 的 JSON。
2. **backend 模型 + 仓储 + 建表**
   - `models/trading.py` 加 `Instrument`；`trading_repository.py` 加 ensure 列表项、seed、upsert/get。
   - verify：`python -c` 起一个 asyncio 调 `ensure_trading_tables()` 后 `get_all_instruments()` 见 5 只 seed；`upsert_instruments([{symbol:'300750.SZ',name:'宁德时代'}])` 后查询命中。
3. **backend proxy + 端点（只读）+ 行情更新回填**
   - `factor_strategy_proxy.instrument_metadata` + `trading.py` 的 `GET /trading/symbols/metadata`（只读主表）。
   - `portfolio_valuation_service.run_eod_valuation` 顺带回填 instruments。
   - verify：`curl '<backend>/trading/symbols/metadata?symbols=600519.SH'` 直接返回主表数据、响应中**无**对 dc 的请求；对历史缺失代码，触发一次盘后估值（`POST /trading/rebalances/trigger` 或估值任务）后再次查，确认已回填。
4. **前端切换名字源**
   - `trading.ts` 加 `getSymbolMetadataApi`；`index.vue` 的 `load()` 改用实际代码集合。
   - verify：`npx vue-tsc --noEmit` 零错误；页面加载后持仓/成交中文名正常显示，含不在原 5 只内的代码。

## 6. 验证结果

- 后端改动 `py_compile` 通过（trading.py / trading_repository.py / factor_strategy_proxy.py / endpoints/trading.py / dc strategy.py）。
- 前端 `vue-tsc --noEmit`：本方案改动文件 `quant/dashboard/index.vue`、`api/core/trading.ts` 零错误（顺带修了两处 `noUncheckedIndexedAccess` 遗留的 `pv[0]`/`pv[-1]` 可能为 undefined 的 TS2532）。
- 接口逻辑自查：
  - dc `GET /strategy/instruments/metadata?symbols=` 返回 `{symbol:{name,industry,list_status}}`（只读，无副作用）。
  - backend `GET /trading/symbols/metadata?symbols=`：查 `instruments` → 缺失代码经 `factor_strategy_proxy.instrument_metadata` 取 dc 名并 `upsert_instruments` 回填 → 合并返回；dc 不可用时仅返回已缓存部分，不报错。
  - 建表：`ensure_trading_tables` 已加入 `Instrument.__table__` 并幂等 seed 5 只演示标的；`exchange` 按代码后缀推导。
- 待人工联调：启动 dc + backend 后，dashboard 加载任意持仓代码应显示中文名；历史缺失代码首次访问即回填。

## 7. 待办 / 遗留

- dc `meta_map` 经确认只含 `name/industry/list_status/list_date`，无 `exchange`/`board`；backend 端 `exchange` 已按 symbol 后缀（.SH/.SZ/.BJ）推导，`board` 暂未落（非展示必需）。
- 存量历史持仓里的代码，首次 dashboard 加载即懒回填，无需单独迁移脚本；若 dc 元数据缺某代码名，仍回退裸代码（可接受）。
- `available-symbols`/`market/quotes` 的 5 只演示标的保持原样，不在本方案范围内改造。
- 实盘模式（live）下同理，instruments 表与模式无关，全局共享。
