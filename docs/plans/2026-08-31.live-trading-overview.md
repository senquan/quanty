# 实盘交易接口 + 量化概览页 + 交易管理页（真实数据对接）

状态：✅ 已实施（后端 + 前端全链路）— 2026-08-31

> 实施时按以下假设推进（用户未答复待确认项，取保守方案，后续可调整）：
> 1. 实盘券商未定 → 只落地 `BrokerAdapter` 抽象，不绑定具体券商；
> 2. 用户隔离分期 → 本期保留单例语义（账户按 `mode` 唯一），`user_id` 仅记录不过滤；
> 3. 净值曲线口径未定 → 首版概览不出曲线，改为"账户权益 + 持仓分布 + 策略/调仓"。

## 一、目标

1. **模拟盘/实盘的持仓、订单、成交统一落库 backend**（现状：内存单例，重启即丢、不隔离用户）。
2. **策划并落地"实盘接口"**：券商适配层，先以 dry-run/模拟兑现，保留真实券商接入点。
3. **量化概览页** `/quant/dashboard` 接真实数据（现状：数据全硬编码）。
4. **交易管理页** `/quant/trading` 接真实数据（现状：数据全硬编码）。

非目标（本期不做）：策略编写/回测改造、多账户并发撮合、Level2 行情。

## 三、架构设计

### 3.1 数据模型（新增 4 表，`backend/app/models/trading.py`）

统一以 **`mode` 字段（`paper` / `live`）区分模拟盘与实盘**，四表皆带，避免双份结构。

| 表 | 关键字段 |
|---|---|
| `trading_accounts` | `id, user_id, mode, broker, account_id, initial_capital, cash_balance, frozen_cash, created_at, updated_at`；`uq(user_id, mode, broker)` |
| `trading_positions` | `id, account_id, mode, symbol, side, quantity, avg_price, last_price, market_value, unrealized_pnl, updated_at`；`uq(account_id, symbol, side)` |
| `trading_orders` | `id, account_id, mode, client_order_id, broker_order_id, symbol, side, order_type, quantity, price, filled_quantity, status, message, source(manual/strategy), strategy_id, created_at, filled_at` |
| `trading_trades` | `id, order_id, account_id, mode, symbol, side, price, quantity, amount, commission, trade_time` |

建表沿用 `Base.metadata.create_all(tables=[...])` + `_INIT_LOCK` 约定，不动 alembic。

### 3.2 券商适配层（实盘接口）`backend/app/services/broker/`

```
        ┌──────────────────────────────┐
        │ BrokerAdapter (抽象基类)      │  connect / get_account / get_positions
        │  base.py                     │  place_order / cancel_order / get_order
        └───────────┬──────────────────┘  get_trades / get_quotes
        ┌───────────┴───────────┐
   SimulatedBroker          MxBroker(妙想)
   (包装现有 HuataiSim      (参考 mx-trader-bridge/trader.py
    Service，行为不变)       默认 BROKER_DRY_RUN=true)
        └───────────┬───────────┘
             factory.get_broker(mode)   ← config: BROKER_MODE / BROKER_DRY_RUN
```

- **风控前置**：下单前必过现有 `RiskControlManager.validate_order`（`huatai_trading.py:131`），实盘额外加"是否允许 live 下单"开关。
- **成交双校验**：实盘下单后必须 `rc=0` + 轮询成交状态确认（借鉴 mx-trader-bridge），避免假成功。
- **降级语义**：`live` 模式未配置凭证/未连通时，**明确报错拒绝下单**，绝不静默退回模拟。

### 3.3 服务层

- `TradingRepository`：account / position / order / trade 的异步 CRUD（含 `_ensure_tables`）。
- `TradingCoordinator`：按 `mode` 路由到对应 Broker → 撮合/查询 → **同步落库**；统一封装"下单后更新持仓与成交"的事务边界。
- 现有 `/orders/internal` 等内部端点改为走 Coordinator，保证 data-cleaner 调仓链路**行为不变**（兼容优先）。

## 六、风险与待确认

1. **实盘券商未定**：仓库内 `huatai_trading` 与 `mx-trader-bridge` **均为模拟盘**，无真实券商凭证。
   方案按 `BrokerAdapter` 抽象 + dry-run 先行落地，真实凭证到位后只补一个实现类。
   → **需你确认**：目标实盘券商（华泰 / 妙想 / 其他），以及是否已申请 API 权限。
2. **用户隔离是破坏性变更**：现有模拟服务是全局单例，所有用户共享同一账户。
   建议**分两阶段**：本期先"落库 + 模式区分"（保留单例语义，用默认账户），用户隔离放下一期，避免一次性改动过大影响现有调仓链路。→ **需你确认**是否接受该分期。
3. **调仓记录在 data-cleaner 侧**：概览/交易页要展示调仓记录需跨域聚合；新增 `mode` 字段涉及 data-cleaner 表变更，需另一条迁移（`factor.factor_strategy_executions` 加列）。
4. **净值曲线**：当前无历史净值/权益快照表，概览页净值曲线需先定义口径（按日快照 or 由成交+持仓反推）。建议本期先落一张 `trading_equity_snapshots` 日快照表，或首版只出"账户权益单点 + 持仓分布"。
5. **并发**：下单落库需加行锁/唯一约束（如 `client_order_id` 唯一）防重复提交，尤其 internal 端点被定时调仓重复触发时。

## 七、实施结果（2026-08-31）

### 7.1 修复的历史 Bug（均阻塞"持仓/调仓"正确性）

| # | 问题 | 位置 | 后果 |
|---|------|------|------|
| 1 | 持仓键用 `f"{symbol}_{order.side.value}"`，买入建 `SYM_BUY`、卖出查 `SYM_SELL` | `huatai_trading.py::_update_position` | **卖出不减仓但照加现金**，持仓只增不减 |
| 2 | 读取 `p.market_price`，而 `Position` 无该字段 | 原 `/positions/internal` | 端点必 500 → data-cleaner 调仓**读不到持仓**，只买不卖 |
| 3 | 风控 `remaining_cash = cash - order_value` 对卖单也生效 | `RiskControlManager.validate_order` | 卖出是**增加**现金，余额偏低时卖单被误拒 |

### 7.2 验证结果

**服务层**（买入 50 → 卖 25 → 清仓）
```
买入   FILLED → 持仓 50
卖出   FILLED → 持仓 25   ✅ bug1 修复生效（减仓）
清仓   FILLED → 持仓 []   ✅ 回灌判据修复生效
成交 3 笔落库，手续费 57.00（28.5 + 14.25 + 14.25）
断言全部通过
```

**跨进程持久化**（核心目标）
```
进程A(buy):  持仓 600036.SH 1000股, cash=954929.5
进程B(read): 持仓 600036.SH 1000股, cash=954929.5   ✅ 从 DB 回灌
```

**HTTP 全链路**（`ASGITransport` 单事件循环，12 个端点全 200）
- `/trading/mode`：paper 就绪、live 未配凭证并给出原因
- `/trading/overview`、`/account`、`/positions`、`/orders`、`/trades`：均返回真实数据
- 下单：`FILLED` ✅
- 超风控下单：`REJECTED` + "订单金额 1900000.0 超过最大限制 100000" ✅（原因已落库）
- live 模式无凭证：`REJECTED` + "未配置妙想凭证（MX_APIKEY），实盘不可用" ✅（不静默退回模拟）
- `/positions/internal`、`/account/internal`、POST `/orders/internal`：恢复正常（bug2 修复）

**前端**：`vue-tsc` 类型检查，本次新增/修改的 4 个文件**零错误**
（仓库内其他文件存在若干既有类型错误，未改动）

### 7.3 遗留 / 后续项
1. **净值曲线**：需先定口径（日快照表 `trading_equity_snapshots` 或由成交+持仓反推），本次未做。
2. **用户隔离**：当前账户按 `mode` 唯一，多用户共享；需改造为按 `user_id` 隔离（破坏性变更）。
3. **实盘券商**：凭证到位后只需新增一个 `BrokerAdapter` 实现类；关闭 `BROKER_DRY_RUN` 前须确认成交双校验。
4. **调仓记录未区分模式**：`factor.factor_strategy_executions` 无 `mode` 字段（表在 data-cleaner 侧，需另一条迁移）。
5. **`/trading/rebalances` 未实测**：依赖已登记的 data-cleaner 实例，本环境未连通。
6. **同步阻塞**：券商适配器为同步 HTTP 调用（与既有代码一致）；实盘调用量增长后建议改 `run_in_executor`。
7. 临时冒烟脚本已删除。
