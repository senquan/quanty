# 三层选股-打分-组合架构设计（配置驱动，分层内容不写死）

状态：🔧 实施中 — P0 数据层 + P1 第一层(hard_rules) 已完成（2026-09-02）；P1 第二层(score_model)/第三层(portfolio) 待实施

## 0. 核心设计原则

> **三层的内容（类别 / 因子 / 权重 / 阈值）全部配置驱动，架构层不写死。**
>
> 架构只提供「三层的执行骨架」与「一套配置 DSL」；
> 具体筛哪些因子、阈值多少、分几类、各类权重、持几只股 —— 全部由配置决定，可随时调整，无需改代码。

- 配置存于**策略 / 回测实例的 JSON**，与因子库一样走「注册-启用」语义。
- 架构代码只认识**通用算子**（`op`、`direction`、`weight`、`role`、`normalize`…），
  不认识「质量/价值/成长」这些业务名 —— 业务名只是配置里的一个 `name` 字符串。

---

## 1. 目标

构建一条 **可回测、可实盘、信号一致** 的三层流水线：

```
候选池(全市场去ST/次新)
   │  第一层：硬性阈值筛选（hard_rules，含流动性/风险门禁）
   ▼
合格池
   │  第二层：分层加权打分（score_model，类别→因子，反向因子，top_k）
   ▼
候选名单(默认前30)
   │  第三层：组合构建与风控（等权/行业上限/溢出/止损/7级卖出信号）
   ▼
目标持仓 + 交易信号
```

要求：
1. 三层内容**全部可配置**，默认值见 §7。
2. **回测与实盘共用同一套信号纯函数**，杜绝两套逻辑漂移。
3. 风控（仓位上限、回撤、状态机）**归口独立风控模块**，组合构建只读取其结果。

## 2. 第一层：硬性阈值筛选

### 2.1 语义

对候选池逐个判定，**全部 `hard_rules` 通过**才进入合格池。规则分两类角色：

| `role` | 用途 | 参与达标评分？ |
|---|---|---|
| `core` | 核心基本面 | ✅ 参与「达标程度评分」/ 熔断 / 基本面淘汰 |
| `liquidity` | 流动性门禁 | ❌ 只做入场过滤 |
| `risk` | 风险门禁 | ❌ 只做入场过滤 |

> **「核心达标阈值指标」本身可配置**（默认取所有 `role: core` 的规则）。
> 通过把某条规则的 `role` 在 `core` 与 `liquidity/risk` 之间调整，即可改变它是否参与达标评分 —— 不改代码。

### 2.2 配置 DSL

```jsonc
"filters": {
  "exclude_st": true,
  "min_list_days": 180,
  "hard_rules": [
    {"factor":"VAL_PE_TTM",         "op":"<=", "value":25,       "role":"core"},
    {"factor":"FND_ROE",            "op":">=", "value":12,       "role":"core"},
    {"factor":"FND_DEBT_RATIO",     "op":"<=", "value":65,       "role":"core"},
    {"factor":"GRO_EPS_GROWTH_YOY", "op":">=", "value":15,       "role":"core"},
    {"factor":"GRO_REV_GROWTH_YOY", "op":">=", "value":10,       "role":"core"},
    {"factor":"LIQ_AMOUNT_20",      "op":">=", "value":50000000, "role":"liquidity"},
    {"factor":"VOL_STD_20_ANN",     "op":"<=", "value":0.40,     "role":"risk"}
  ]
}
```

- `op ∈ {<=, >=, <, >, ==, !=}`，通用比较算子。
- 阈值单位在因子侧统一（见 §5 口径）。

### 2.3 动态阈值

每条 `hard_rule` 可附 `dynamic` 子对象，用**相对阈值**替代固定 `value`：

```jsonc
{"factor":"VAL_PE_TTM", "op":"<=", "value":25, "role":"core",
 "dynamic": {"mode":"quantile", "quantile":0.7}}
```

| `mode` | 含义 | 阶段 |
|---|---|---|
| `quantile` | 取全市场该因子的分位点作阈值（如 `0.7` = 只保留后 30%） | **一期实现** |
| `index_relative` | 随基准指数估值联动（如沪深300 PE 分位映射） | **二期** |

> 固定值与动态阈值**二选一**（配置校验时互斥）。

## 3. 第二层：分层加权打分

### 3.1 语义

对合格池按「类别 → 因子」两层加权打分，取 `top_k`（默认 30）。

- **类别权重**（类间加权）与**因子方向**（正/反向）都在配置里。
- 类内多因子默认**等权**（`intra: equal`，后续可扩展类内权重）。
- **反向因子用 `direction: -1`**（PE / 负债率 / 低波取负），避免「负权重被归一化破坏」。

### 3.2 配置 DSL

```jsonc
"score_model": {
  "mode": "hierarchical",     // hierarchical | flat(兼容旧)
  "normalize": "zscore",      // zscore | rank | minmax
  "top_k": 30,
  "classes": [
    {"name":"质量", "weight":0.25, "intra":"equal", "factors":[
        {"code":"FND_ROE",            "direction": 1}]},
    {"name":"价值", "weight":0.20, "intra":"equal", "factors":[
        {"code":"VAL_PE_TTM",         "direction":-1},
        {"code":"VAL_DIV_YIELD",      "direction": 1}]},
    {"name":"成长", "weight":0.20, "intra":"equal", "factors":[
        {"code":"GRO_EPS_GROWTH_YOY", "direction": 1},
        {"code":"GRO_REV_GROWTH_YOY", "direction": 1}]},
    {"name":"负债", "weight":0.15, "intra":"equal", "factors":[
        {"code":"FND_DEBT_RATIO",     "direction":-1}]},
    {"name":"动量", "weight":0.10, "intra":"equal", "factors":[
        {"code":"MOM_RET_20",         "direction": 1},
        {"code":"REL_STR_20",         "direction": 1}]},
    {"name":"低波", "weight":0.10, "intra":"equal", "factors":[
        {"code":"VOL_STD_20",         "direction":-1}]}
  ]
}
```

- `classes` 数组**长度、名字、权重、因子全部可调**；架构只按 `Σ(class_weight × class_score)` 合成。
- 归一化在**类内**做（每类先对自身因子 normalize 后合成类得分），再类间加权。

## 4. 第三层：组合构建与风控

### 4.1 组合构建

```jsonc
"portfolio": {
  "max_positions": 10,          // 最终持仓数【可配置，默认10】，从 top_k 候选中按得分+约束选出
  "weight_mode": "equal",       // equal | score_prop | risk_parity(二期)
  "industry_cap": 0.30,
  "industry_cap_enabled": false, // ← 待 industry 数据补齐后改 true（见 §6.5）
  "position_limit_pct": 0.80,    // 仓位上限【归口风控模块】
  "position_limit_mode": "manual",     // manual | dynamic
  "position_limit_dynamic": {          // dynamic 时生效
    "indicator": "INDEX_PE_QUANTILE",
    "low_quantile": 0.9, "high_quantile": 0.6
  }
}
```

**溢出逻辑（可配置语义）**：
```
max_exposure = 权益 × position_limit_pct        // 例 100万 × 80% = 80万
需求 = 当前持仓市值 + 计划买入金额
若 需求 > max_exposure:
    溢出 = 需求 − max_exposure
    在【现有持仓】中按 达标程度评分(margin, min) 升序卖出，直至 ≤ max_exposure
```

### 4.2 止损与状态机

```jsonc
"stop": {
  "per_stock_pct": -0.08,       // 个股止损
  "portfolio_dd_pct": -0.12,    // 组合回撤
  "recovery_days": 5,           // 恢复观察期【默认5】
  "reentry_mode": "once"        // 重进模式【默认一次性】once | repeat
}
```

状态机：`NORMAL ⇄ RISK_OFF`，由风控模块维护，组合构建只读。

### 4.3 卖出信号（7 级优先级 × 时机矩阵）

沿用上一轮定义的 7 级信号（止损 / 基本面淘汰 / 阈值熔断 / 行业超限 / 排名掉出 / 止盈 / 再平衡），
按**优先级 + 触发时机（盘中/收盘/调仓日）**矩阵执行。信号与时机均在配置中，不写死。

```jsonc
"sell_signals": [
  {"name":"per_stock_stop",  "priority":1, "timing":"intraday"},
  {"name":"fundamental_fail","priority":2, "timing":"close"},
  {"name":"threshold_breach","priority":3, "timing":"close"},
  {"name":"industry_cap",    "priority":4, "timing":"rebalance"},
  {"name":"rank_drop",       "priority":5, "timing":"rebalance"},
  {"name":"take_profit",     "priority":6, "timing":"close"},
  {"name":"rebalance",       "priority":7, "timing":"rebalance"}
]
```

## 10. 实施进度（2026-09-02）

### 10.1 已完成：P0 数据层 + P1 第一层（hard_rules）

**代码**：`data-cleaner/app/strategy/engine.py`
- `normalize_hard_rules(rules)`：DSL 校验与归一化。无效 `op` / 未注册 `factor` 以 warning 忽略；`role` 非法降级为 `core`；`dynamic` 仅支持 `quantile`（其它 mode 降级固定阈值）。
- `apply_hard_rules(as_of, frames, rules, restrict=None)`：返回 `(qualified, info)`。
  - `qualified` = 候选集（restrict 或全市场有因子值标的）中**通过全部规则**（core+liquidity+risk 三类角色都参与通过性判定）的集合。
  - `info` = `{rules:[{factor,op,role,threshold,available,passed,total}], detail:{symbol:{rule_index:bool}}, qualified}` 供诊断与前端展示。
  - 因子当日无数据 → 该规则无人通过 → 合格池为空；固定值与动态阈值二选一（见 §2.3）。
- `scores_at(..., restrict=None)`：新增 `restrict` 形参，仅保留合格池标的参与打分与 z_map。
- `compute_target` / `run_backtest`：**回测与实盘共用同一套第一层信号纯函数**（设计原则 #2）。
  - 加载因子帧时取 `打分因子 ∪ hard_rules 因子` 并集（避免硬阈值因子未加载）。
  - `compute_target` 输出新增 `hard_filter` 字段（合格池只数 + 各规则阈值/通过数）。
  - `normalize_filters` 现返回 `hard_rules`。

**验证**：纯函数单元验证（合成数据，无需 DB）全部通过 —— 归一化剔除、固定阈值全通过判定、quantile 动态阈值（线性插值）、因子缺失→合格池空、`scores_at` restrict 过滤。临时脚本已清理。
