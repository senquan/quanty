## 💡 经验总结

1. **AI代码生成 → 人工Review → Mock移除 → API对接** 的标准迭代流程需要至少5个commit（参考 `13d7208` → `b288e5b` → `bf24b78` → `0b4aafe` → `360c119`），建议为AI提交的每个大Feature预留对应数量的修复/对接commit

2. **Vben Admin 迁移关键点**: Vite project → Vben Admin 的迁移不是单纯的包升级，而是整个应用架构的重构。重点注意：(a) Router定义方式差异 (b) Store module格式 (c) Theme/CSS变量系统

3. **WSL2 mirror模式网络**: Fetch/Push单次TCP连接约150s-3min，建议:
   - terminal timeout ≥ 400s
   - retry间隔 30-60s (不要太长以免消耗时间资源)
   - max_retries = 3 已够用（第3次失败概率极低）

4. **docs/plans/ 文档驱动开发**: 
   - `*.task.md` (任务清单) + `*.report.md` (日报) + `*.insights.md` (经验记录)
   - 形成完整的开发追溯链 → commit diff可追溯到每日报告和经验
   - **建议**: 每次代码PR后补充一条insight entry到最新日期的insights.md

5. **Feature branch长期不同步的危害**: feature/hermes-corder 已有47+天未与master sync（自上次merge PR#7起），累积62个commit diverge。**最佳实践: 每7-10天同步一次**，避免大规模conflict
