# 基本面历史回填方案

- 状态：**待实施**
- 日期：2026-09-08
- 关联：今日盘后核查发现 09-07 早期截面 `value`/`growth`/`sentiment` 全 NaN（见
  `docs/` 今日对话）。实测确认该 NaN **非行情回填写坏**（`abnormal(异常写坏)=0`），
  而是**基本面三张表的历史覆盖缺口**——本文解决之。
- 范围边界：本方案只回填**基本面历史**（`daily_basic` / `finance_reports`），与价量
  `raw_bars` 回填（另见 09-08 修复）正交，不碰交易、不碰策略编排。

---

## 1. 目标

让因子库在 ~2020/2021 起（与 `raw_bars` 可用区间对齐）对全宇宙全交易日具备完整基本面，
消除 `value`(PB/PS/PE百分位)、`growth`(营收/净利同比)、`sentiment`(换手率)、`size`(市值)、
`fundamental`(ROE/负债率) 在早期日期的系统性 NaN，使长周期回测可用。

**不做**：不重算价量类因子（其 NaN 仅来自个别标的上市首日附近的回看边界，属固有）；
不修 `stock_info.industry`（全空，是 metadata_refresh 子问题，另立 issue）。

## 2. 现状证据（带文件行号）

### 2.1 覆盖度实测（2026-09-08 查询 `factor` 库）

| 表 | 行数 | 日期范围 | 关键列非空数 |
|---|---|---|---|
| `daily_basic` | 932,435 | 2021-10-08 ~ 2026-09-08 | `total_mv`=932,435(满)、`circ_mv`=932,435(满)、`pe_ttm`=19,639、`pb`=27,485、`ps_ttm`=27,728、`dv_ttm`=18,541 |
| `finance_reports` | 164,006 | 2020-06-30 ~ 2026-09-08 | `rev_growth_yoy`=68,731(42%)、`eps_growth_yoy`=69,079(42%)、`roe`=135,149、`debt_ratio`=135,725、`eps`=160,598 |
| `stock_info` | 2,039 | — | `industry`=0(全空)、`list_date`=2,039 |

判读：
- `daily_basic` 实际只覆盖**最近约 168 个交易日**（全宇宙），早期日期无行；估值列仅最近 3~5 日有值。
  `total_mv/circ_mv` 满 → 市值派生脚本（见 2.3）已对近期窗口跑通。
- `finance_reports` 的 `roe/debt/eps` 自 2020 较完整；`rev/eps 同比`仅 42%，即成长历史缺口。
- 空集结论：早期日期 NaN 的根因是这两张表的历史缺失，非因子计算 bug。

### 2.2 因子依赖链路（代码证据）

`_merge_fundamental`（`app/tasks/factor_build.py:27-93`）合并三表：
- `daily_basic`（`factor_build.py:44-56`，列 `pe_ttm,pb,ps_ttm,div_yield,turnover_rate,turnover_rate_f,total_mv,circ_mv`）→ **value / size / sentiment(换手)**
- `finance_reports`（`factor_build.py:58-82`，列 `rev_growth_yoy,eps_growth_yoy,roe,debt_ratio,eps_ttm`）→ **growth / fundamental / VAL_PE_TTM 回退**
- `stock_info`（静态）→ 行业/上市日/股息，非日期相关

受影响因子（`app/factors/fundamental.py` + `app/factors/sentiment.py`）：
- `value`：`VAL_PB`(pb, :39)、`VAL_PS_TTM`(ps_ttm, :53)、`VAL_PE_TTM`(eps_ttm或pe_ttm, :15)、`VAL_DIV_YIELD`(dividend_ttm或dv_ttm, :67)、`VAL_PE_PERCENTILE`(pe_ttm或价, :88)
- `growth`：`GRO_REV_GROWTH_YOY`(rev_growth_yoy, :112)、`GRO_EPS_GROWTH_YOY`(eps_growth_yoy, :128)
- `fundamental`：`FND_ROE`(roe, :163)、`FND_DEBT_RATIO`(debt_ratio, :180)
- `sentiment`：`TURNOVER_RATE`(turnover_rate, :26)、`TURNOVER_RATE_F`(turnover_rate_f, :41)

### 2.3 已存在的可复用资产

- `backfill_valuation_history.py`（仓库内脚本）：用 pandadata `get_share_float` × 收盘价
  **推导** `total_mv/circ_mv`（及 `float_share/circulation_a`），UPSERT 仅写这 4 列
  （`ON CONFLICT DO UPDATE` 只改 mv 两列，不动 pe/pb 等）。`total_mv` 满即其产物。
- `FundamentalSource._fetch_akshare`（`app/ingestion/fundamental_source.py:592-626`）：
  调 akshare `stock_a_indicator_lg(symbol,start,end)`，**单标的一次返回全历史** pe_ttm/pb/ps_ttm/dv_ttm。
- `FundamentalSource.fetch_growth_akshare_bulk`（`fundamental_source.py:351-402`）：
  akshare `stock_yjbb_em(date=报告期)`，**每报告期 1 次调用**取全市场营收/净利同比。
- `fundamental_store.upsert_daily_basic` / `upsert_finance_reports`（`app/storage/fundamental_store.py:57-152`）：
  全列 UPSERT，`COALESCE` 保证分项刷新互不覆盖。

### 2.4 诊断修正（避免误判范围）

先前"整类全 NaN"是把**类别内任一列为 NaN 的标的**计入，属过计数：
- `value 全 NaN` = `VAL_PB`/`VAL_PS_TTM` 因该日 `daily_basic` 无行而 NaN；`VAL_PE_TTM`/`VAL_DIV_YIELD`/`VAL_PE_PERCENTILE`
  可由 价 × eps_ttm/dividend_ttm 计算（eps_ttm 自 2020 可用），未必全 NaN → **真实缺口是 PB/PS/PE百分位/换手依赖的 daily_basic 列**。
- `sentiment 全 NaN` = `TURNOVER_RATE`/`TURNOVER_RATE_F` 缺换手；量比/成交额分位纯价量不受影响。
- `growth 全 NaN` = **真实缺口**：营收/净利同比历史仅 42%。

⇒ 方案按**列**精确回填，不盲目重算。

## 3. 架构与改动清单

```
数据来源(历史)                     存储                     因子类别
─────────────────────────────────────────────────────────────
akshare stock_a_indicator_lg  ┐
  (pe/pb/ps/dv 逐标的全历史)   ├─► factor.daily_basic ─► value / size / sentiment(换手)
pandadata share_float×close   ┘   (total_mv/circ_mv/float_share 推导)
raw_bars volume / float_share ─► 推导 turnover_rate(_f) 入 daily_basic

akshare stock_yjbb_em(逐报告期) ─► factor.finance_reports ─► growth(营收/净利同比)
  (rev/eps 同比)                  (roe/debt/eps 已较完整)
```

改动清单（最小改动，外科手术式）：
1. **新增** `data-cleaner/backfill_daily_basic_history.py`：遍历宇宙，逐标的拉 akshare 估值 +
   推导 mv/换手，UPSERT `daily_basic`。含 akshare 节流/重试 + 断点续跑 + 分批日志。
2. **复用** `FundamentalSource.fetch_growth_akshare_bulk`：以"全季列表(2020Q2~最近)"调用，
   回填 `finance_reports` 成长历史（建议包一层 `backfill_growth_history.py` 做断点+日志，
   或直接扩展 `refresh_growth` 接受 periods 入参）。
3. **不新增** 调度：回填为一次性历史任务，手动/后台跑，不接入每日调度（避免与 `fundamental_refresh` 冲突）。
4. 回填后**一次性重算**受影响因子截面（`build_factor_library` 指定类别/区间）。

## 4. 分步步骤（每步带 verify）

### Step 0 — 市值/股本历史化（复用既有脚本）
- 运行 `backfill_valuation_history.py --start 20211001 --end 20260908`（已存在），
  将 `total_mv/circ_mv/float_share/circulation_a` 推导写入全历史。
- 注意：`.BJ` 被跳过（pandadata 不支持），其市值后续可用 akshare 新浪源补（脚本已留 TODO）。
- **verify**：`SELECT count(*), min(trade_date), max(trade_date), count(total_mv) FILTER(WHERE total_mv IS NOT NULL) FROM factor.daily_basic;` → 行数应较 93 万大幅增长，total_mv 非空接近全量，min 推到 ~2021。

### Step 1 — 估值列历史化（pe/pb/ps/dv，逐标的 akshare）
- 新建 `backfill_daily_basic_history.py`：
  - 遍历 `get_a_share_universe()`，对每个 symbol 调 `FundamentalSource(token=None, provider="akshare")._fetch_akshare(symbol, "20210101", "20260908")`
    取 pe_ttm/pb/ps_ttm/dv_ttm（stock_a_indicator_lg 单标的全历史）。
  - 同一标的用 pandadata `get_share_float` 取 `float_share`/`circulation_a`（若 Step0 已落库可直接读 `daily_basic`）。
  - **推导换手率**：`turnover_rate = volume / float_share * 100`、`turnover_rate_f = volume / circulation_a * 100`
    （volume 来自 `raw_bars` 按 symbol+date 左连），避免再调外部换手接口。
  - `upsert_daily_basic`（全列 UPSERT；与 Step0 的 mv 写入通过 `COALESCE`/`ON CONFLICT` 互不覆盖，
    注意确认不会把 Step0 的 total_mv 清掉——实现上每次写入该 (symbol,date) 全部已知列即可）。
  - akshare 节流：加全局 ~1~2 call/s 节流 + 失败重试（参考 `backfill.py` 的 `_spend_permit`/`_tighten_rate`），
    限频/网络抖动走重试；**断点续跑**（state 文件记已完成的 symbol），分批日志。
- **verify**：`SELECT count(pe_ttm) FILTER(WHERE pe_ttm IS NOT NULL), count(pb) FILTER(WHERE pb IS NOT NULL), count(turnover_rate) FILTER(WHERE turnover_rate IS NOT NULL) FROM factor.daily_basic;` → 非空数应接近行数（剔除确实退市/无数据标的）。

### Step 2 — 成长历史化（rev/eps 同比，逐报告期 akshare）
- 生成全季列表：`[(y, m, d) for y in 2020..2026 for (m,d) in ((3,31),(6,30),(9,30),(12,31)) if date<=today]`。
- 调用 `FundamentalSource(...).fetch_growth_akshare_bulk(periods)`（每期 1 次 `stock_yjbb_em`），
  `upsert_finance_reports`。包断点+日志（扩展 `refresh_growth` 或新建 `backfill_growth_history.py`）。
- **verify**：`SELECT count(rev_growth_yoy) FILTER(WHERE rev_growth_yoy IS NOT NULL), count(eps_growth_yoy) FILTER(WHERE eps_growth_yoy IS NOT NULL) FROM factor.finance_reports;` → 非空数接近行数（覆盖 2020 起全季）。

### Step 3 — 重算受影响因子截面
- 运行 `build_factor_library(start="2021-01-01", end="2026-09-08", categories=["value","size","sentiment","growth","fundamental"])`。
  （`partial=False` 全量覆盖这些类别的截面；价量类 momentum/volatility/liquidity/quality 不重算以免无谓 IO。）
- **verify**：对各早期日期（2024-01-02 / 2024-07-01 / 2025-01-02）读截面，按列统计 NaN：
  `VAL_PB/VAL_PS_TTM/TURNOVER_RATE/GRO_REV_GROWTH_YOY/GRO_EPS_GROWTH_YOY` 的 NaN 应降至仅"上市首日附近回看边界"与真正退市标的，类别整体不再系统性全 NaN。

### Step 4 — 清理与文档
- 删除本次新增的临时诊断脚本（`_dbg_*.py`、`_diag_*.py` 等），保留正式 `backfill_*.py`。

## 6. 待办 / 风险

- **akshare 稳定性/限频**：逐标的 5557 次 `stock_a_indicator_lg` 需节流+重试+断点；个别标的可能缺历史（跳过记 log）。

- **与每日 `fundamental_refresh` 冲突**：历史回填是一次性任务，跑完即止；日常刷新仍只刷最新日，二者写入 `(symbol,date)` 维度不重叠（历史任务写老日期，刷新写最新日），无并发冲突。
- **`stock_info.industry` 全空**：正交问题，由 metadata_refresh 另修，不阻塞本方案。
- 本方案与 09-08 价量回填**正交**，建议独立后台运行，不阻塞交易调度。
