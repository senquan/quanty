## 技术经验分类

### 📡 网络诊断经验

- **Proxy连接失败特征**: `Failed to connect to 127.0.0.1 port 4780 after 0 ms: Connection refused`
  - `after 0 ms` 表明 proxy 进程存活但拒绝新连接（非超时）
  - 可能原因：proxy 进程挂起、SSL 证书过期导致上游断开、防火墙规则变更
  - **排查步骤**: 
    1. `curl -I https://github.com`（测试直连）
    2. `ss -tlnp | grep 4780`（检查 proxy 端口监听状态）
    3. 确认 proxy 上游是否可达

- **重试策略**: 当前实现3次重试 × 30秒间隔（共1分30秒），对于 cron job 场景是合理的。但建议后续增加：如果连续2天 fetch 失败，检查 proxy 配置是否需要更新或切换代理方式。

## 💡 经验总结

1. **Proxy容错**: cron job 场景下网络不可达是常态而非例外。建议在任务执行前增加网络可用性检查（`ping -c1 github.com`或curl测试），根据结果跳过或重试远程操作，避免不必要的时间浪费。

2. **增量提交模式**: 本项目报告文件采用多轮迭代提交策略（同日多次commit: `e28dcb8` → `87cd1d8` → `cb54903 (final)`），最终版本以`(final)`标识。这种模式保证即使部分提交未推送，最终版本也有完整信息。

3. **路线图文档即API契约**: `quant-closed-loop-roadmap.md`不仅是规划文档，还是功能开发的参考规范。新开发任务完成后需对照Milestone表格打勾确认，确保需求全覆盖。

4. **文件命名趋势**: 项目正从中文文件名（`因子-短期开发计划.md`）向英文命名（`short-term-dev-plan.md`）迁移，消除跨平台兼容性问题。建议新项目全部使用英文命名。

5. **前端静态资源配置**: Logo、主题色等品牌资源存入 `public/static/` 目录，通过preferences系统动态加载。新增同类配置时保持"配置文件统一入口 + 静态资源独立目录"的双层结构。
