## 技术经验分类

### 🐛 Bug修复

- **update_menu_status 返回语句位置错误**
  - 位置：`backend/app/api/api_v1/endpoints/menus.py`
  - 问题：`return {"message": "菜单状态更新成功"}` 位于函数体内死代码区域（`await db.refresh(menu)` 之后的缩进位置，但随后有 `@router.get("{menu_id}/children")` 的新路由定义）
  - 修复：将 return 语句移入函数体（提前 return），移除底部不可达的旧 return
  - **经验教训**：在函数中添加新路由装饰器时，注意不要与旧代码残留的 return 冲突，确保 return 在函数 return 之前

- **CORS 配置变量名不一致**
  - 位置：`backend/main.py`
  - 问题：`settings.allowed_origins_list` → `settings.ALLOWED_ORIGINS`
  - 原因：settings 中的常量命名风格不一致，`allowed_origins_list` 是小驼峰，`ALLOWED_ORIGINS` 是全大驼峰
  - **经验教训**：环境变量/配置常量统一使用 UPPER_CASE 命名风格（Python 最佳实践），读取时在 settings.py 中定义 `ALLOWED_ORIGINS = self.allowed_origins_list` 以保持兼容

### ♻️ 重构优化

- **SQLAlchemy 从异步回归同步（AsyncSession → Session）**
  - 变更：`quant.py` 和 `dependencies.py` 中 `AsyncSession` → `Session`，同时移除了 `Query`（fastapi）和 `or_` 的导入
  - 移除的端点：`PUT /strategies/{id}`（更新策略）、`DELETE /strategies/{id}`（删除策略）
  - 移除的 schema：`StrategyUpdate`（因删除端点而不再需要）
  - 简化：`get_strategies` 移除了 `search` 参数和 `or_` 查询，仅保留 `skip/limit` 分页
  - **经验教训**：
    1. FastAPI + SQLAlchemy 2.x 推荐使用同步 Session（async context manager），避免 `AsyncSession` 的复杂性
    2. 移除功能时需要级联清理：schema → endpoint → dependency type → import
    3. 使用 `model_dump(exclude_unset=True)` 替代 `dict()` 是 Pydantic v2 最佳实践（代码注释中有 H1-5 标记）

- **字符串转义风格统一**
  - 变更：`menus.py` 中所有字符串使用 `\"\"\"` → `\\\"\\\"\\\"` 转义格式
  - 影响：router 装饰器路由字符串、docstring、HTTPException detail 均有变更
  - **经验教训**：如果项目使用 AST 转换或其他模板生成工具，需要注意三重引号在特定场景下的转义问题

### 📦 依赖变更

- **移除 SQLAlchemy async 依赖**
  - `sqlalchemy.ext.asyncio.AsyncSession` → `sqlalchemy.orm.Session`
  - 不再需要 `asyncpg` 或 `aiosqlite` 异步驱动（或从依赖中移除）
  - **注意事项**：FastAPI 的 `Depends(get_db)` 仍返回同步 Session，确保 `get_db` 生成器中使用 `sessionmaker` 而非 `async_sessionmaker`

- **清理 `Query` 导入**
  - FastAPI 的 `Query` 从 `quant.py` 中移除，因为 `skip/limit` 改为默认值参数（`skip: int = 0` 代替 `Query(0, ge=0)`）
  - **经验教训**：当参数有默认值且无需 validator 约束时，使用普通 Python 默认值更简洁，仅在需要 `ge/le/regex` 等约束时使用 `Query()`

## 💡 经验总结

1. **批量精简 > 增量优化**：本次变更删除了 1455 行代码而只添加了 56 行，说明项目中大量功能（策略更新/删除、菜单搜索、async 抽象层）被识别为不必要，这是健康的代码瘦身
2. **Pydantic v2 迁移标志**：`model_dump()` 替代 `dict()` 是 Pydantic v2 的标志，项目中应全局检查是否有遗漏点
3. **不可达代码检测**：`update_menu_status` 中的旧 return 语句是典型的"追加式编码"遗留问题 → 定期重构函数内部结构
4. **级联清理模式**：删除一个 feature 时需要按 `schema → endpoint → dependency → import → config` 的顺序清理
5. **配置常量命名一致性**：避免在 settings 中使用小驼峰和大驼峰混用，统一 UPPER_CASE
