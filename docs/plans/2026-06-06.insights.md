### 🚀 New Feature: Mock Data Removal
- **功能名称**：移除前端 Mock 数据，接入真实 API
  - 涉及模块：quant.py（后端）、前端 strategy 列表、回测图表
  - 技术要点：
    - 修复 `quant.py` 类型错误：`Session` → `AsyncSession`
    - 添加 P0 修复：`quant.py` 中 8 处 `Session` 全部替换为 `AsyncSession`
    - 所有同步方法改为异步：`db.commit()` → `await db.commit()`
  - 设计模式：异步数据库交互模式（AsyncSession + await）

### 🐛 Bug修复
- **问题描述**：`quant.py` 类型错误导致运行时崩溃
  - 根本原因：混用同步 SQLAlchemy Session 和异步操作 await
  - 解决方法：全部替换为 AsyncSession，使用 `await db.execute(select(...))` 语法
  - **预防建议**：新接口统一使用 `AsyncSession`，同步/异步接口严格隔离
  
- **问题描述**：策略 PUT/DELETE 端点缺失
  - 根本原因：后端只实现了 GET/POST，漏掉了 PUT/DELETE
  - 解决方法：补全 PUT/DELETE 端点，含级联删除逻辑
  - **预防建议**：CRUD 操作应作为一组同时实现，使用 `@router.{method}` 装饰器

## 经验改进建议

1. **CRUD 完整性检查**：新增一个资源时，应同时检查 4 个 HTTP 动词（GET/POST/PUT/DELETE）是否都已实现
2. **类型安全**：数据库交互层应统一使用一种模式（全部异步或全部同步），避免混用
3. **前端 API 对接检查点**：后端新端点上线时，需同步更新前端对接状态
4. **测试先行**：每个 P0/P1 修复应伴随对应的单元测试，防止回归
