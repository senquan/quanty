### 💡 经验总结

1. **网络连通性影响主干同步**
   - WSL2 环境下 GitHub HTTPS 连接不稳定（单次连接可达 134 秒才超时）
   - 建议：配置 Git proxy（如 `git config --global http.proxy socks5://localhost:7890`）或改用 SSH 协议

2. **Feature branch 长时间未更新**
   - 距上次开发提交已超两周，rebase master 时可能合并冲突增多
   - 建议：每日任务 runner 应定期 rebase，保持分支与主线同步

3. **无任务文件 = 无需动作**
   - `{TODAY}.task.md` 不存在时自动跳过任务执行阶段，避免空跑
   - 经验：可考虑用 weekly summary 替代 daily report 模式减少无效生成

4. **retry_network 函数超时过长（~120秒/次）**
   - 3 次重试总计浪费 ~7 分钟运行时间
   - 建议：首次超时降至 30 秒，快速失败 + cron 机制更合理

5. **Cron job 场景下无交互**
   - 已正确识别为 cron 场景，无需等待用户输入
   - 网络失败时创建重试任务的兜底机制完善
