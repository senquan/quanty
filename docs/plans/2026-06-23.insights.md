### 🐛 Bug修复

#### 后端 API 统一响应格式（Commit bf24b78）

- **问题描述**:
  各 backend endpoint 返回格式不一致——部分直接返回 Pydantic model 实例，部分返回 dict 字面量。前端需同时适配 `[T]`、`{ message: string }`等多类格式。

- **根本原因**:
  FastAPI endpoint 的 `response_model` 定义与 return 值不匹配，缺少统一包装层。

- **解决方法**:
  引入 `app.schemas.response.Response` 统一响应封装类：
  ```python
  # 修改前
  @router.get("/strategies")
  async def get_strategies(...):
      return result.scalars().all()  # 返回 [Strategy]
  
  # 修改后
  @router.get("/strategies", response_model=Response[List[Strategy]])
  async def get_strategies(...):
      return Response.success(data=result.scalars().all())  # { code, msg, data }
  ```

- **影响范围**:
  - `auth.py` — 新增 `/codes` 权限码接口
  - `menus.py`, `quant.py`, `roles.py`, `trading.py`, `user.py`, `users.py`
  - `api.py` — API 挂载点调整
  - `frontend/src/api/core/auth.ts` — 前端 auth header 处理同步更新

- **预防建议**:
  1. FastAPI endpoint 应始终使用统一的 `Response.success()` 包装返回
  2. TypeScript 前端请求拦截器应统一解包 `{ code, data, msg }` 格式
  3. API 文档生成（Swagger）会自动反映 `response_model=Response[T]`，提升可读性

## 💡 经验总结

### 1. FastAPI 统一响应封装模式

```python
# 通用 wrapper 模式（可从 app.schemas.response.Response 复用）
from app.schemas.response import Response

@router.get("/resource", response_model=Response[List[ResourceSchema]])
async def list_resources(
    db: AsyncSession = Depends(get_db),
    current_user: User = Depends(get_current_user)
):
    # ... 业务逻辑
    return Response.success(data=items)  # { "code": 200, "msg": "success", "data": [...] }
```

**好处**:
- 前端统一处理 `{ code, data, msg }` 结构，无需判断返回类型
- Swagger 文档自动带上标准响应 schema
- auth middleware 可统一校验 `response_model`

### 2. Vue Router 模块化最佳实践

将路由配置拆分为独立文件（`routes/modules/{feature}.ts`），好处：
- **职责分离**：每个业务域管理自己的路由注册
- **易于维护**：新增模块只需创建一个新文件，在 main router 中 `addRoute()` 即可
- **按需引入**：配合 `lazy-loaded` 组件加载，减少首屏体积

### 3. Mock 数据层解耦策略

项目中使用了 `factor-data.ts`（静态 mock data）和 `factor-service.ts`（模拟服务层）分离模式：
```
factor/
├── types.ts          # TypeScript interfaces
├── mock/
│   ├── factor-data.ts   # 固定测试数据
│   └── factor-service.ts # Promise-based mock service
```

这种 `数据定义 → Mock数据 → MockService` 三层解耦方式，可以平稳过渡到真实 API。

### 4. Pydantic V2 model_dump() 迁移注意事项

| V1 | V2 | 说明 |
|----|----|------|
| `.dict()` | `.model_dump()` | **注意方法名变化** |
| `.dict(exclude_unset=True)` | `.model_dump(exclude_unset=True)` | 行为一致 |
| `.parse_obj(data)` | `Model.model_validate(data)` | 解析入口变化 |
