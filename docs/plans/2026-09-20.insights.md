### 🐛 Bug修复
- **画像超额收益窗口形同虚设**（d2fbac6，D-1）
  - 根本原因：`ORDER BY timestamp ASC LIMIT 1/2` 后在 Python 里取 rows，`EXCESS_WINDOWS=[20,60]` 根本没进 SQL → avg_excess_20d ≡ avg_excess_60d（14/14 同值）
  - 解决方法：基准序列载入内存当交易日历，bisect 定位 idx，个股与基准同取 `[idx, idx+w]`；样本不足置 NULL + `sample_insufficient=true`，不给假值
  - 预防建议：**"参数没进查询"是静默失败第一类**——窗口/期限类参数必须出现在 SQL 或可断言的测试里（见 3cd19de 的"改回去必失败"反向自检）
- **hfq_close 断供两层根因**（d2fbac6，D-2）
  - 根因 1：增量源 pandadata 无复权因子接口，新行恒 NULL；根因 2：upsert 路径 `hfq_close = EXCLUDED.hfq_close`，NULL 把已回填值冲掉
  - 解决：k 常数法（hfq = close × median(hfq/close)，cv≈5e-15）+ 迁移 017 改 `COALESCE(EXCLUDED.x, raw_bars.x)`
  - 预防建议：**upsert 对"回填型字段"必须 COALESCE 保留旧值**；增量链上任何一环节断供都要有断供检测
- **画像跨天重算覆盖历史**（d9333ed，D-9）
  - 根本原因：唯一键 (profile_key, profile_type, profile_version) 且 version 恒 'v1' → 每日重算原地覆盖，历史截面不可复现（实测 0.9612→0.5683→0.8881 漂移）
  - 解决：加 as_of 日期列，唯一键扩 4 列；读取口径统一 max(as_of)（`computed_at` 是写入时间，同日重跑会刷新，不能判"最新"）
  - 预防建议：**"最新"语义要区分 as_of（知识截止）与 computed_at（写入时刻）**；回测可复现性要求结果按 as_of 版本化
- **prompt_version 跨仓库隐式契约**（109f4fd，D-1 同类）
  - 风险：backend 硬编码 `PROMPT_VERSION="v2"`，dc 侧 prompts.py 是另一个字面量；dc 升 v3 后 /mentions 静默返回空列表且两侧测试全绿
  - 解决：启动期校验库内 max(prompt_version) 与常量一致性，**只告警不阻断启动**（配置/数据问题不该拖垮后端）
  - 预防建议：跨仓库/跨进程的字面量契约要么共享定义，要么加启动期校验 + WARN
- **WS 长连接静默失效**（dada997）
  - 现象：dc 的 WS 客户端静默停止重连，backend 侧只表现为 connections=0 且无人察觉（09-10/09-11 两次）
  - 解决：watch job 周期比对"已注册清洗服务"与"实际 WS 连接"，300s 阈值告警、60s 检查周期、600s 同服务防刷屏
  - 预防建议：**"connections=0" 是故障信号不是正常态**——常驻长连接必须有对侧主动探测 + 告警
- **normalize_text 跨格式副本漏判**（a14b6a9）：清洗微信/markdown 样板残渣后再做转载判定
- **dc 启动即崩回归**（3cd19de）：迁移 013 重建已废弃的 3 列唯一索引；配套 `test_migrations_no_dead_index.py` 183 行防回归

## 💡 经验总结
1. **静默失败三兄弟**：参数没进 SQL（D-1）、跨仓库字面量契约漂移（prompt_version）、回写 NULL 冲掉已回填值（D-2）——共同点是"测试全绿但结果错误"。对策：关键口径加"改回去必失败"的反向自检 + 启动期契约校验 + upsert 用 COALESCE。
2. **审计驱动的批量处置模式高效**：D-1~D-14 编号登记 → 逐项 fix+test+docs 三件套 → 审计文档同步数字（D-14 重跑后同步）。一个 693 行审计文件是整批变更的索引，值得在大型修复战役中复制。
3. **"最新"的语义必须显式建模**：as_of（知识截止）vs computed_at（写入时刻）混淆是数据回测类系统的高频陷阱；版本化键设计时就要把日期维度放进去。
4. **常驻连接的对侧探测**：WS 断连告警 watch job（阈值/周期/防刷屏三参数）是"connections=0 无人察觉"这类故障的通用解法；同模式可用于任何长连接/定时任务的活性监控。
5. **安全基线**：口令绝不进源码，统一从 app 配置（.env）解析；且必须配防回归扫描测试（f9adc10），否则下一个人还会写回去。
