## 0. 修订说明

### v1 → v2
据决策改为：backend 单实例作 **WS 服务端**、dc 作客户端拨出（1 对多）；确认因子库查看走 backend 本地；明确 dc→backend 反向推送用于信号通知与因子更新广播。

### v2 → v3（本轮：两处根基性纠正 + 九项决策）

| # | v2 表述 | v3 纠正 |
|---|---|---|
| 1 | "全量因子列表由 backend 本地存储" | **dc 是因子的源(SoT)**；backend 的 `factor_registry` 只是**副本**，存在意义仅是前端查看时不打 dc |
| 2 | 因子更新广播列为 Phase 4 可选优化 | 广播 = **副本同步通道，属根基**；与连通**同批上线** |
| 3 | 信号在 S1/S2 间待定 | 信号为**预留框架**，仅定义消息类型与处理钩子，**不实现生成逻辑**；明确两种模式 |
| 4 | 未涉及撮合成交 | dc 直接撮合成交时**需回推成交报告**并落库，让 backend 感知持仓变化 |
| 5 | 未明确副本内容边界 | 明确：副本 = 元信息 + 最新一期指标快照；**不含 bulk、不含时间序列**（本次不做序列，折线图维持降级） |

### 九项已确认决策

| # | 决策项 | 结论 |
|---|---|---|
| 1 | 信号颗粒度 | **只预留消息类型与钩子**（`strategy.compute` / `signal.generated`），不实现生成逻辑 |
| 2 | 副本一致性 | **最终一致** —— 广播触发增量同步 + **每日对账**；开启 `ENABLE_FACTOR_SYNC` |
| 3 | 成交回报 | dc 直接撮合成交**需回推 `event.execution.report`** 并落库 |
| 4 | 首期范围 | 连通/重连/outbox **与**因子副本广播**同批上线**，先立根基 |
| 5 | 序列（折线图） | **本次不做**；副本维持"只存最新一期"，折线图继续降级 |
| 6 | Redis | **完全可选**；无 Redis 时降级为**内存有界 LRU + 幂等兜底** |
| 7 | dc 实例数 | **当前 1 个、未来会多** → 从第一天即按 1 对多设计，`instance_id` 必填 |
| 8 | "远程浏览/导入"路径 | **保留**（显式手动动作，继续 HTTP） |
| 9 | 对账发现冗余因子 | **标记 `orphaned` + 告警，不自动清理** |
| 10 | `api_key` 明文 | **已治理**（AES(Fernet) 加密存储 + 多 key 逗号并存与轮换；存量明文启动期自动重加密；解密失败回退明文并告警） |

## 1. 确认的约束

1. backend **单实例**，作 **WebSocket 服务端**（`/ws/dc`）；N 个 dc 实例作**客户端**拨出，**1 对多**。
2. **因子以 dc 为源(SoT)**：因子在 dc 计算、落 parquet、经 `/api/v1/factor` 暴露；backend 的 `factor_registry` 是**副本**。
3. **副本内容**（本次不变）：元信息 + **最新一期**指标快照；**不含**因子 bulk（逐标的逐日矩阵）、**不含**时间序列。折线图维持降级。
4. **副本一致性**：最终一致，广播触发增量同步 + 每日对账。
5. **信号**：仅预留框架，不实现生成。
6. **成交回报**：dc 直接撮合成交模式下需回推报告并落库。
7. **bulk 边界**：因子矩阵、correlation(N×N)、parquet/区间数据**一律不走 WS**，继续 HTTP。
8. **推送不得阻塞 EOD 主流水线**：异步化，失败仅入 outbox 并告警。
9. **Redis（已确认）**：**完全可选，本设计不依赖 Redis**。断线补发由 dc 侧 outbox 驱动（dc 自持 `last_acked_seq`）；backend 去重在无 Redis 时降级为**内存有界 LRU + 业务幂等兜底**。
10. **实例规模（已确认）**：dc **当前 1 个、未来会多** → 从第一天即按 **1 对多**设计，`instance_id` 为必填身份，连接注册表按 `instance_id` 区分连接。

### 2.1 因子所有权与副本内容

| **backend 副本** | `factor_registry`（`backend/app/models/cleaner.py:57-78`） | 元信息 + `metrics` JSON（**最新一期快照**） |

- `backend/app/models/cleaner.py:75-76` 注释明确：

### 2.2 通讯现状

**backend → dc（全部 HTTP）**

| 调用点 | dc 端点 | 频率 | 数据量 |
|---|---|---|---|
| `cleaner_gateway.poll_qos`(`:92-104`) | `GET /api/v1/qos` | **30s × 每 active 服务** | 小 |
| `cleaner_gateway.sync_factors`(`:243-288`) | `GET /api/v1/factor?include_metrics=true` | 60min（`_factor_sync_job`） | 中（元信息+指标） |

| `factor_proxy.correlation`(`:130-136`) | `POST /api/v1/factor/correlation` | 用户 | **大(N×N)** |
| `factor_library.list_factors`(`:47-60`) | — | 用户 | **本地读，不调 dc** |

- `ENABLE_FACTOR_SYNC` **默认 False**；同步语义"**只更新已入库记录、不新增**"，**无对账机制** → 副本可静默漂移（本次纠正暴露的最脆弱点）。
- 底层 `_get_json`(`:61-66`) 每次新建 `httpx.AsyncClient`，**无重试/退避/熔断**（全仓 0 命中）；超时 `5s`/`30s`。
- `cleaner_services.api_key`(`:30`) 注释称 AES，**实为明文**（已确认一并治理）。

**dc → backend：0 处。**
`BACKEND_BASE_URL`(`app/core/config.py:48`)、`STRATEGY_INTERNAL_TOKEN`(`:50`) 为**死配置，零引用** → 可直接复活用于 dc→backend 鉴权。

**状态/进度（既有缺陷）**
- `cache.publish_status`(`app/storage/cache.py:68-70`) 名为 publish，实为 Redis **单键 SET**（TTL 86400），**无消费者**；30s 心跳 `{"status":"alive"}` 会**覆盖**同 key，冲掉流水线报告。
- `/pipeline/status` 读**进程内全局** `_last_report`(`app/api/v1/pipeline.py:45`)：重启即丢。
- 两侧**均无** WS / SSE / StreamingResponse。

### 2.3 信号现状（两侧皆空白）

- dc 无 signal 实体（`signal` 文件名 0 个）。团队语境的"发信号"= `POST /api/v1/strategy/scores`(`app/api/v1/strategy.py:161`) → `engine.compute_target`(`app/strategy/engine.py:935`)，**pull 模型**，唯一调用者是 backend `rebalance_service.py:121`；结果**不落库不缓存**。
- 其输出(`:1027-1044`)为 `{date, weights, scores, hard_filter, holdings:[{symbol,score,weight,industry,z_scores}]}`，**缺 `strategy_id` 与 `direction`**；`top_n` 默认 30(`:941`)。
- backend **无**任何 signal / alert / notify / webhook 模块或表。
- 因子与行情均日频 → 信号天然**盘后日频**，不可能盘中产生。

## 3. 拓扑

```
              ┌─────────────────── backend (:8000, 单实例) ───────────────────┐
              │                                                                │
              │  WS Server  /ws/dc   （握手鉴权 X-Internal-Token）             │
              │       ▲                                                        │
              │       │ 连接注册表（进程内 dict: instance_id → ws）            │
              │       │   · last_seq / ack  · 在线状态                          │
              │  ┌────┴──────────────────────────────────────────────┐        │
              │  │ 事件分发 + 幂等去重（内存 LRU，Redis 可选增强）      │        │
              │  │   status / presence / pipeline / factor.updated     │        │
              │  │   signal.generated(预留) / execution.report         │        │
              │  └────┬──────────────────────────┬───────────────────┘        │
              │       │                          │                             │
              │  副本增量同步 + 每日对账      signals / execution_reports      │
              │       ▼                          ▼                             │
              │  factor_registry(副本)      (新增表，本轮仅建模)               │
              └───────┬────────────────────────────────────────────────────────┘
                      │  WSS（dc 拨出）                    │ WSS
                      ▼                                    ▼
              ┌────────────────┐                   ┌────────────────┐
              │ dc 实例 #1     │                   │ dc 实例 #N     │
              │ （当前仅 1 个） │                   │ （未来扩展）    │
              │ WS Client      │                   │                │
              │ · 重连/退避    │                   │                │
              │ · 本地 outbox  │                   │                │
              │ 因子 parquet   │                   │                │
              │ (SoT)          │                   │                │
              └────────────────┘                   └────────────────┘

      bulk HTTP（因子矩阵 / correlation / parquet / 远程浏览导入）── 保持 HTTP，不走 WS
```

**要点**
- backend **单副本** → 连接注册表退化为**进程内 dict**，v1 设想的 Redis 选主/fan-out 全部消失。
- dc 当前 1 个、未来多 → **首版即按多实例实现**：`instance_id` 必填、注册表按 `instance_id` 区分、重连按 `instance_id` 错峰。
- dc 是客户端 → **重连与 outbox 都在 dc 侧**（发送方缓冲）。
- 双向复用：dc 上推事件；backend 沿同一连接下发 `ack` / `resync` / `req.*`。

## 4. 协议

### 4.1 信封

```jsonc
{
  "v": 1,                 // 协议版本，用于协商；不匹配则拒绝并回退 HTTP
  "id": "01J...",         // 消息唯一 id（ULID），接收端据此幂等去重
  "type": "event.factor.updated",
  "ts": "2026-09-04T09:42:07.725+08:00",
  "seq": 1024,            // 发送方连接内单调递增，驱动 ack 与断线补发
  "corr_id": "01J...",    // 请求-响应关联（响应必填）
  "reply_to": null,       // 预留：跨实例路由
  "payload": { },
  "meta": { "chunk": null } // 分片信息：{index, total, blob_id}
}
```

- 单帧上限 **256KB**（压缩后）；超出必须分片或改走 HTTP。
- 压缩 `permessage-deflate`；大二进制帧关闭压缩（避免内存放大）。

### 4.2 消息目录

**dc → backend（推送主方向）**

| type | 说明 | 性质 |
|---|---|---|
| `hello` / `bye` | 握手上报 `instance_id`、能力、协议版本 | 新增 |
| `ping` / `pong` | 应用级心跳 | 新增 |
| `event.status` | QoS + 健康 + 版本 | 【迁移】替代 30s `poll_qos` |
| `event.presence` | 上线/下线/降级 | 【迁移】 |
| `event.pipeline.{started,progress,step,finished,failed}` | EOD 8 步、因子构建、回填进度 | 【迁移】替代进程内 `_last_report` |
| **`event.factor.updated`** | 因子定义/指标变更通知（**只带 code + 版本，不带矩阵**） | 【新增·根基】副本同步触发源 |
| `event.signal.generated` | 信号产出 | 【**预留**，不实现生成】 |
| **`event.execution.report`** | dc 直接撮合成交的成交回报 | 【新增】 |

**backend → dc（下发）**

| type | 说明 | 性质 |
|---|---|---|
| `ack` | 按 `seq` 确认，驱动 dc 清理 outbox | 新增 |
| `resync.request` | 重连后请求补发（自 `last_seq` 起） | 新增 |
| `strategy.compute` | 提交策略请求计算信号 | 【**预留**】 |
| `req.qos` / `req.scores` / `req.relay.prices` | 小载荷控制类 | 【迁移·可选，后置】 |

> backend→dc 的 HTTP 目前工作正常，该方向**后置**，首期只做 `ack` + `resync`。

### 4.3 bulk 边界（不变）

因子矩阵、correlation(N×N)、parquet/区间数据**一律 HTTP**。理由：单连接内大消息会造成**队头阻塞**（拖死心跳与控制消息）、单帧内存放大、背压失效。WS 只传"哪些因子变了"。

> **"远程浏览 / 导入"路径（已确认：保留）**
> `GET /api/v1/cleaner/{code}/factors`（`cleaner.py:191-212`）与 `POST .../import`（`:215-236`）作为**显式手动动作**继续保留在 HTTP 通道上，不走 WS。
> 已知隐患：其 `DEFAULT_TIMEOUT=5.0`（`cleaner_gateway.py:25`）对全量拉取偏紧 → 记为**待办**（建议上调或改后台任务），**不改变保留决定**。

## 5. 因子副本同步（根基）

### 5.1 副本内容边界（本次明确）

| 内容 | 是否在 backend 副本 | 说明 |
|---|---|---|
| 因子元信息 | ✅ | code/name/category/frequency/formula/description |
| 最新一期指标 | ✅ | `{as_of_date, ic_mean, ic_std, ir, sharpe_ratio, max_drawdown, win_rate}` |
| **因子 bulk（逐标的逐日矩阵）** | ❌ | **永远留在 dc parquet**，同步只传元信息 |
| **指标时间序列** | ❌ | **本次不做**；dc 有 `factor.metrics` 序列但不同步，折线图维持降级 |

### 5.2 同步机制

```
dc 因子定义/指标变化（EOD 因子构建后、或用户在 dc 侧增删改）
        │
        ▼  event.factor.updated{ service_code, codes:[...], version, ts }
backend 收到 → 标记本地 factor_registry 对应行 stale
        │
        ▼  触发后台增量同步（HTTP，只拉变更项）
   更新 factor_registry（元信息 + 最新一期 metrics）
```

- **WS 只传 code + 版本号**，真实数据由后台 HTTP 增量拉取（延迟不敏感）。
- 取代 60min 定时全量轮询 → **变更驱动增量同步**，是数据量上的最大收益。

### 5.3 每日对账（必须新增）

现状"只更新已入库记录、不新增、**无对账**" → 副本会静默漂移。新增每日对账任务：

| 检查 | 方法 | 处置 |
|---|---|---|
| 缺失（dc 有、backend 无） | 比对 dc 因子 code 集合 vs 本地 `factor_registry` | **补入并告警** |
| 冗余（backend 有、dc 已删） | 反向比对 | **标记 `orphaned` + 告警，不自动清理**（已确认，避免误删已启用因子） |
| 指标陈旧 | 比较 `metrics_synced_at` 与 dc `as_of_date` | 触发重同步 |

- 对账结果落日志 + 指标（缺失数/冗余数/陈旧数），异常告警。
- **处置口径（评审已确认）**：缺失 → 补入并告警；冗余 → **仅标记 `orphaned` + 告警，不自动清理**。

### 5.4 需开启的配置

`ENABLE_FACTOR_SYNC` 当前**默认 False** → 必须开启，否则广播只能"标记 stale"，副本仍会漂移。

## 6. 信号预留框架（不实现生成）

### 6.1 两种模式

```
模式 A（信号模式）：
  backend 提交策略 ──► dc 用行情/因子计算 ──► 推 signal.generated ──► backend 风控 ──► 最终决策 ──► 执行

模式 B（直接成交模式）：
  backend 提交策略 ──► dc 计算并直接撮合成交 ──► 回推 execution.report ──► backend 记账/感知持仓
```

**发信号的目的，就是让流程回到 backend 走风控与最终决策。**

### 6.2 预留消息结构

```jsonc
// backend → dc: strategy.compute（预留）
{"strategy_id":"uuid","config":{...},"as_of":"2026-09-03","mode":"signal|direct"}

// dc → backend: event.signal.generated（预留）
{
  "signal_id": "01J...",        // 幂等键 = strategy_id + as_of（唯一约束防重复）
  "strategy_id": "uuid",
  "as_of": "2026-09-03",
  "trade_date": "2026-09-04",
  "holdings": [
    {"symbol":"600519.SH","score":1.82,"weight":0.041,"direction":"buy",
     "industry":"白酒","z_scores":{"MOM_20":1.2}}
  ],
  "diagnostics": {"hard_filter":{...},"weights":{...}}
}
```

- 现 `compute_target` 输出**缺 `strategy_id` 与 `direction`**，预留时需补齐（**仅补字段定义，不改算法**）。
- 量级：策略数 × ≤30（`engine.py:941`），单包可承载，**无需分片**。

### 6.3 明确不做

- ❌ 不实现信号生成逻辑
- ❌ 不新增信号调度任务
- ❌ 不改 `compute_target` 算法
- ✅ 只定义消息结构、handler 入口（占位返回）、落库表建模

## 7. 成交回报通道

```
dc 直接撮合成交 ──► event.execution.report ──► backend 落库 ──► 更新持仓/账本
```

```jsonc
{

  "strategy_id": "uuid",
  "executed_at": "2026-09-04T14:32:10+08:00",
```

## 8. 鉴权

| 项 | 方案 |
|---|---|
| 握手 | 复活死配置 `BACKEND_BASE_URL`（改 `ws://`/`wss://`）+ `STRATEGY_INTERNAL_TOKEN`；dc 在**HTTP 升级请求头**携带 `X-Internal-Token`（server-to-server 可自由设头） |
| 校验 | backend 复用 `trading.py:432` `verify_internal_token` 思路做 WS 握手校验 |
| 身份 | 连接绑定 `instance_id`（dc 自报，须唯一）+ `service_code`（对应注册表） |
| 传输 | 生产强制 `wss://`；内网 `ws://` 需网络隔离 |
| 防护 | 单帧上限、单连接未 ack 消息数上限、连接数上限、消息速率限流 |
| **api_key 治理（已确认：一并治理）** | `cleaner_services.api_key`(`:30`) 注释称 AES **实为明文** → 改为**加密存储**，支持多 key 并存与轮换；迁移期兼容已有明文值（读取时优先解密，失败回退明文并日志告警） |

## 9. 可靠性

### 9.1 重连（dc 侧）
- 指数退避 + 抖动：`0.5s → 30s` 上限，±20% 抖动；
- **按 `instance_id` 哈希错峰**，防多实例重连风暴（惊群）；
- 连续失败超阈值 → 熔断，降频探测。

### 9.2 outbox（发送侧 = dc）
- dc 事件先落**本地 outbox**（文件/SQLite，TTL 24h）；
- 收到 backend `ack(seq)` 后清理；重连后自 `last_acked_seq + 1` 补发；
- outbox 容量上限 + 积压告警；超限丢弃低优先级（进度事件可丢，`factor.updated` / `execution.report` 不可丢）；
- backend 按事件 `id` 去重：**默认内存有界 LRU**（如最近 1 万条 id）；Redis 可用时用 SET + TTL 增强跨重启去重。两条路径都以**业务幂等**兜底（`factor.updated` 按 code+version 幂等、`execution.report` 按 `report_id` 唯一键）。

### 9.3 心跳
- WS 原生 ping 15s + 应用 `ping` 30s；连续 3 次无响应判死重连；
- **LB/代理空闲超时必须大于心跳间隔**（WS 上线最常见的生产事故点）+ TCP keepalive。

### 9.4 不阻塞主流程（硬约束）
- 推送**异步化**，失败仅入 outbox 并告警，**绝不阻塞 EOD 主流水线**。

### 9.5 降级回退
- WS 不可用时状态类回退低频 HTTP 轮询（仅对未连接实例，5min）；
- 请求类回退 HTTP；降级状态须打点告警，避免"静默降级"。

### 9.6 Redis 定位（已确认：完全可选，非依赖）

- **断线补发不依赖 backend 持久化 `last_seq`**：dc 自持 outbox 与 `last_acked_seq`，重连后由 **dc 主动**自 `last_acked_seq + 1` 补发；backend 无需记住水位。
- **去重不依赖 Redis**：默认内存有界 LRU；Redis 可用时增强为跨重启去重。
- 结论：Redis 在本设计中**仅作增强项**（去重持久化、状态缓存），**缺失时功能完整，仅去重窗口变短**，由业务幂等兜底。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 副本漂移未被发现 | 前端看到错误因子信息 | **每日对账**（Phase 3 必做）+ 告警；冗余仅标记不自动删 |
| `ENABLE_FACTOR_SYNC` 未开 | 广播只能标记 stale，收益打折 | Phase 3 明确纳入开启清单并验收 |
| 推送阻塞 EOD | 数据流水线被拖垮 | 异步化 + outbox；**硬约束** |
| outbox 无限增长 | 磁盘爆 | 上限 + TTL 24h + 积压告警 |
| 断线期间事件丢失 | 因子漏更新、成交漏记账 | `seq` + outbox 补发 + `id` 去重 |
| 无 Redis 时去重窗口变短 | 重启后短暂重复投递 | 内存 LRU + **业务幂等兜底**（唯一键/幂等键） |
| LB 空闲超时踢连接 | 连接频繁断开 | 心跳间隔 < LB 超时；TCP keepalive；上线前验证 |
| 多实例重连风暴 | 压垮 backend | 抖动 + 按 `instance_id` 错峰 + 熔断 |
| 静默降级无人察觉 | 改造"看起来成功" | 降级次数打点 + 告警 |
| `api_key` 加密迁移出错 | 所有 dc 连接鉴权失败 | **已落地**：Fernet 加密存储 + **解密失败回退明文并告警**；存量明文启动期自动重加密，无需停机迁移（见 `app/core/credential.py` / `cleaner_gateway.migrate_api_keys`） |
| 协议演进不兼容 | 升级即故障 | 版本协商 + 回退 HTTP + 契约测试 |
