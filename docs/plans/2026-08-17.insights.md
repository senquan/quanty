## 💡 经验总结

### 1. 全栈开发模式
此项目的 commit (360c119) 是典型的**全栈一次提交覆盖**:
- Backend API (路由注册 + 端点实现)
- Frontend components (Vue组件集群: 因子卡/编辑器/热力图/回溯测试)
- Documentation (路线图 + 开发计划)
- Assets (logo更新)
- Config (preferences.ts + vite.env)

**经验**: 一次 commit 做多层变更时，commit message 需涵盖多个维度。当前 `feat: 因子库相关页面` 较为笼统，建议细化为 `feat(frontend+backend): 因子库页面组件及菜单API端点`

### 2. Vue 3 + Element Plus 前端架构
从文件名和设计模式看：
- **组件化设计**: factor-card, factor-editor-modal, correlation-heatmap — 每个功能独立封装
- **热图可视化**: CorrelationHeatmap 用于因子相关性分析，数据量大时需考虑性能优化（WebGL/WebGPU）
- **偏好设置模块**: `preferences.ts` 管理用户配置 → Vuex/Store 模式

### 3. FastAPI + Pydantic 后端架构
从 commit bf24b78 (接口修正) 覆盖 7+ 端点来看:
- Endpoints 按功能模块化: auth, menus, quant, roles, trading, user(s)
- models/user.py → SQLAlchemy ORM 模型
- **经验**: 多端点批量修改时容易遗漏参数同步，建议在修改接口后运行 `pydantic` 校验

### 4. AI辅助开发实践
commit `13d7208: add factor UI(by: Qoder Quests Qwen3.7-Max)` 表明：
- **经验**: 前端模板代码/组件生成适合给 AI coding tool，减少样板代码工作量
