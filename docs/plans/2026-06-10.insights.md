## 技术要点回顾（基于最近一次经验提取）

### 🚀 Mock 数据移除 (feat: remove mock)
- **涉及模块**：quant.py、前端 strategy 列表、回测图表
- **关键变更**：`Session` → `AsyncSession` 替换，所有同步方法改为 await
- **设计模式**：异步数据库交互（AsyncSession + await），前端 API 真实对接

### 🐛 P0 Bug 修复 (fix: P0 problems)
- **问题描述**：quant.py 混用同步 SQLAlchemy Session 和异步操作 await，运行时必崩溃
- **解决方法**：8 处 `Session` 全部替换为 `AsyncSession`
- **预防建议**：新接口统一使用 `AsyncSession`，同步/异步严格隔离
- **代码规范参考**：使用 `await db.execute(select(...))` 语法处理查询和更新

### 🐛 PUT/DELETE 端点补全 (fix: P0 problems)
- **问题描述**：前端策略列表无法修改，后端缺 PUT/DELETE 端点
- **解决方法**：为策略 API 补全 CRUD 全部操作（GET/POST/PUT/DELETE）
- **预防建议**：新增资源时同时实现 4 个 HTTP 动词

## 💡 今日经验总结

1. **同步/异步不混用**：SQLAlchemy 项目中，数据库交互层应统一使用一种模式。最近一次提交验证了全部改用 async 的必要性——混合使用会导致 AttributeError 运行时崩溃（如 `Session` 对象没有 `.commit()` 方法在 await 上下文中）。
2. **Git rebase 前先 stash**：本次操作中有未提交的 staged changes，stash + rebase + stash pop 是安全的工作流。
3. **网络重试机制有效**：fetch 第 1 次即成功，但脚本设计了 3 次 × 30 秒的重试，覆盖了间歇性网络问题。
