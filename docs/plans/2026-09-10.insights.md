### 🐛 Bug修复

- **pandera `WRONG_DATATYPE`（a847886）**：整数价 CSV 经清洗后 dtype 为 int64，
  触发 pandera 类型校验失败。
  - 根本原因：价格列在数据全为整数时 pandas 推断为 int64，而 schema 声明 float64；
    清洗流程未做 dtype 归一化。
  - 解决方法：统一转 float64（`pipeline/schema_check.py` +1 行归一化）。
  - 预防建议：**凡价格/收益/比率类数值列，落库前显式 `astype(float64)`**，不要依赖 pandas 推断；
    schema 校验前插入"类型归一"步骤。数值精度问题在 CSV→DB→因子计算链路上极易复现。

- **`/pipeline/run` 因子列缺失崩溃（7e3b548）**：`None of [...] are in the [columns]`（FND_ROE/FND_DEBT_RATIO）。
  - 根本原因：计算因子前未合并基础数据（估值/财报），`cleaned` 只有 OHLCV、没有因子依赖列。
  - 解决方法：**先 `factor_build._merge_fundamental(cleaned)` 合并基本面，再逐因子 `compute_factor`**；
    逐因子 try/except，单因子失败只 warning 不中断；保存截面时 `codes = [code for ... if code in latest.columns]`
    过滤不存在的列，空 category 直接 continue。
  - 预防建议：**"先合并依赖列、再按 code 取列"** 是因子计算的标准顺序；单因子计算必须容错（隔离失败），
    按列名取数前先做 `if col in df.columns` 防御，避免一个脏因子拖垮整条流水线。

- **数据链路整治（ad5eb11）**：`cleaner_gateway.py`(258 行) 重构、`pandadata_source.py` 复权修复、
  `raw_store.py`、`migrate_dc_to_backend.py` 迁移脚本。
  - 根因背景（architecture.md §3.3）：pandadata 回补**未传 `adjust`** 默认不复权 → `adj_factor`/`hfq_close` 全表 NULL，
    清洗层 `adj_close = close` 直接透传，导致**所有价格类因子**（动量/波动/技术/情绪）用不复权价、IC/IR 同步失真。
    决定性证据：2,000 条单日跌幅超板块跌停的记录（1,360 只），如比亚迪 2025-07-29 337.00→111.42（-66.94%），
    经 10 送 8 转 12 派 39.74 复权后与 111.42 吻合 → 确为除权假跳空。
  - 解决方法：`factor.raw_bars` 修复为**前复权 qfq**（假跳空 2000→0 条），并补齐**后复权 hfq_close**（5555/5555 覆盖）。
  - 预防建议：**复权口径是因子/回测正确性的地基**。判据要分板块阈值（主板 ±10%/创业·科创 ±20%/北交所 ±30%）
    且**排除上市前 5 个交易日**（无涨跌幅限制，那段暴跌是真实炒作非除权）——v1 判据（< -21%）高估到 2126 条。
    `adj_factor` 仍全 NULL（各源拿不到复权因子），**勿依赖该列**，用 `hfq_*` 派生列。qfq 以最新日为锚会漂移，**需定期重拉**。

## 💡 经验总结

1. **数据位置决定计算位置（Data locality over code locality）**。回测归口 dc 的决策是全批变更里最有价值的架构经验：
   A 股数据在 dc，backend 两库隔离拿不到，回测放 backend 就是"引擎长在没有数据的一侧"。
   跨 HTTP 逐标的取数（N 次往返压在请求链路上）远慢于本地 `repository.load()`。
   **判断一个计算该放哪个服务，先看它的数据在哪、访问是内存级还是网络级。**

2. **复权口径是因子/回测正确性的地基，且极易隐蔽失真**。pandadata 默认不复权导致 2000 条除权假跳空、
   所有价格类因子 IC/IR 同步失真，却长期没被发现（`adj_close=close` 透传太自然）。
   判据要分板块阈值 + 排除新股上市前 5 日。教训：**数据"看起来对"不等于对，要用业务规则（涨跌幅限制）做定量校验。**

3. **数值 dtype 归一化必须在 schema 校验前显式做**。整数价 → int64 → pandera WRONG_DATATYPE，
   这类 bug 只在"数据恰好全为整数"时触发，平时测试覆盖不到。**价格/比率类列落库前 `astype(float64)` 应成默认动作。**

4. **"先合并依赖列、再按 code 取列" + 单因子容错隔离**是因子流水线的标准模式。
   7e3b548 的崩溃（FND_ROE 取不到列）源于计算因子前没合并基本面；修复后逐因子 try/except、
   按 `if code in columns` 过滤——**一个脏因子不应拖垮整条流水线**。

5. **outbox 模式放在"负责重连的一方"**。WS 事件链路里，dc 是客户端并负责重连，所以 outbox 缓冲+补发归 dc，
   backend 只需 ack + 去重，无需持久化水位，Redis 变成可选项。**"谁持有连接状态，谁持有 outbox"**，
   事件先落盘(JSONL)再发送，崩溃最多丢最后一行，TTL+容量双上限、超限优先丢非关键事件。

6. **凭证治理：加密存储 + 平滑迁移 + 失败降级三件套**。api_key 明文→Fernet 加密，
   迁移期明文兼容（告警一次）、启动期自动重加密、解密失败按明文回退（不致全量鉴权挂）。
   **安全加固不能"一刀切"，要保留迁移期兼容与失败降级路径，否则上线即事故。**

7. **业务结果与系统异常要分开建模**。broker `place_order` 被拒返回 `status=REJECTED` + `message`（业务结果），
   只有券商不可用才抛 `BrokerError`（系统异常）。未识别 mode 一律安全兜底到模拟盘。**"拒单"不是错误，是正常业务流。**

8. **过程性脚本与正式代码分离**。本批变更带出大量 `_verify_*.py`/`_dc_probe*.py`/`_r1a_*.py` 探测/验证脚本，
   随后被 gitignore 治理移出仓库。**探索期脚本要有约定前缀 + 及时归档，避免污染主干。**
