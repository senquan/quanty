## 💡 经验总结

1. **模块化 API 架构**: FastAPI项目中，新增端点采用"独立文件 + 主路由导入注册"模式 — 只需在主api.py添加import和include_router两行即可暴露新接口，低耦合易维护。建议所有新增端点遵循此模式。

2. **路线图文档即设计契约**: `quant-closed-loop-roadmap.md`是一份高质量的技术决策文档——它以量化指标的硬性标准（IC>0.03、IR>0.5）定义了因子质量，以明确的里程碑和时间线定义了开发节奏。这种"文档驱动开发"的方式降低了跨阶段沟通成本。**建议**：每新增一个重要功能模块前，先在路线图中定位对应的Milestone。

3. **前后端分离的演进**: accessMode从`'mixed'`变为`'frontend'`表明前端正在独立化，logo配置也说明品牌识别在逐步完善。这为后续微前端拆分奠定了基础。**建议**：保持preferences集中管理，新增功能时同步更新配置。

4. **UI一致性修复模式**: 字号、颜色等视觉样式问题应全局扫描而非逐个组件修复。本次改动涉及6个组件的同一类型变更（10px→11px），说明存在统一的设计规范。**建议**：将常用尺寸变量化（如定义CSS变量或Tailwind config）。

5. **中文文件名迁移**: 项目中存在多个中文版名文件，逐步迁移到英文名可避免WSL/Linux/Git URL中的编码问题。但需注意git rename追踪而非先删后建。
