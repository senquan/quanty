### 📊 量化交易闭环路线图文档

**文件**: `docs/memo/quant-closed-loop-roadmap.md` (215行)

**架构图**:
```
因子数据层 → 因子选股层(Alpha Model) → 交易执行层(Order Engine) → 风控反馈层(Risk Monitor)
     ↑                                                                         │
     └───────────────────── 迭代优化 ◀────────────────────────────────────────┘
```

**阶段划分**(约6个月总周期):
| 阶段 | 里程碑 | 时间估算 |
|------|--------|----------|
| 阶段一:因子数据搜集 | M1-M3 (数据基础+基本面因子+技术面拓展) | 5-7周 |
| 阶段二:因子驱动选股 | M4-M6 (单因子检验+多因子合成+回测验证) | 6-8周 |
| 阶段三:执行交易 | M7-M9 (券商API接口+模拟盘+小资金实盘) | 8-12周 |
| 阶段四:风控反馈迭代 | M10-M11 (风控体系+策略迭代闭环) | 持续进行 |

**量化指标约定**: IC > 0.03, IR > 0.5（因子质量阈值）；年化收益>20%，最大回撤<15%（策略达标线）

**关键设计决策**:
- 数据源: Tushare/AKShare(免费), Wind(商业)
- 存储: PostgreSQL
- 交易接口: QMT(迅投)/Ptrade/掘金量化
- 回测成本: 双边万三手续费 + 0.1%滑点

**可复用模板**: 路线图文档结构可作为新项目规划参考，含阶段里程碑表、验收标准、风险提醒。

## 🐛 Bug修复

### 组件字号一致性

**问题描述**: 6个因子相关Vue组件中的辅助/注释文本（如"IC均值""夏普比率""最大回撤"等标签）统一使用`text-[10px]`，在部分设备上可能导致可读性问题。

**解决**: 系统性地将所有辅助文字从`text-[10px]`调整为`text-[11px]`，提升视觉舒适度。涉及文件：
- backtest-studio.vue
- correlation-heatmap.vue  
- efficacy-deep-dive.vue
- factor-card.vue
- factor-editor-modal.vue
- factor-library.vue

**预防建议**: 建立CSS变量或Tailwind config统一字号，避免硬编码分散多处。

## 💡 经验总结

1. **FastAPI模块化架构的最佳实践**：每个独立功能模块创建单独的端点文件，通过主api.py的 `include_router()` 聚合。这种设计保持了代码的低耦合和高内聚，方便单模块开发测试和多人并行协作。新增一个端点只需"新建文件 + import + include_router"三行即可上线。

2. **路线图文档驱动开发**：`quant-closed-loop-roadmap.md`是一份高质量的技术规划文档。它包含完整的架构图（文本ASCII）、阶段里程碑、每个Milestone的具体任务表格、验收标准量化指标（IC/IR阈值、收益/回撤达标线）和关键风险提醒。建议每次新增功能前，先对照路线图确认对应Milestone，保持开发的系统性。

3. **Vue组件批量一致性改动**：同一批组件中的同类视觉问题应一次性全局扫描修复，而非逐个组件修改。本次涉及6个组件字号统一调整，体现了"关注点分离+视觉规范"的工程意识。

4. **SVG Logo嵌入项目**：将品牌Logo以SVG格式放入public静态资源目录，通过前端的logo配置系统统一管理。注意dark模式的sourceDark也需要同步提供，否则暗色主题下可能显示异常（当前已预留配置但文件未到位）。

5. **量化研究的标准流程**：从路线图中可总结出因子研究的标准工作流——数据收集 → 单因子检验(IC/IR) → 多因子合成选股 → 回测验证 → 实盘执行 → 风控反馈迭代。这套流程具有行业通用性，可作为量化团队的标准化SOP参考。
