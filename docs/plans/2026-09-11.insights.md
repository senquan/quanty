## 💡 经验总结

延续昨日提炼、今日仍有效的关键经验（摘自 2026-09-10 insights，供后续任务参考）：

1. **回测归口决策**：回测一律放 dc（因子引擎侧），backend 只做网关转发——根因是行情/因子数据在 dc 的 `factor.raw_bars`，两库隔离（quant_db / factor_db）下 backend 拿不到数据。"回测引擎不能长在没有数据的那一侧"。
2. **WS outbox 在发送侧**：dc 是 WS 客户端，缓冲/重连/补发归 dc；backend 只按 `seq` 回 ack、按事件 `id` 去重，无需持久化水位，Redis 完全可选。事件先落盘（JSONL 追加）再发送，崩溃最多丢最后一行。
3. **拒单是业务结果，不是异常**：broker 层 `place_order` 被拒返回 `status=REJECTED` 的 Order（附 message），只有券商不可用（无凭证/连不上/鉴权失败）才抛 `BrokerError`。未识别 mode 一律安全兜底为模拟盘。
4. **管道-过滤器 + 优雅降级**：dc 清洗管线六步 Transformer 链，每步产出 report；pandera 结构校验在缺库时降级为手工校验，不硬依赖可选组件。
5. **fine-grained PAT 不跟随 GitHub 仓库重命名重定向**：仓库 `quanty-feature` → `quanty` 后旧 URL 直接 404，需手动 `git remote set-url`；token 提取用 bash 子串而非 awk（见 daily-task-runner skill 的踩坑记录）。
