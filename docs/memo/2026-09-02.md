## 一、背景

## 三、修复的缺陷

### 3.1 多板块 `universe` 归一化失效（DC）

`app/strategy/engine.py::_normalize_universe()` 对列表元素一律套
`_symbol_digits(u)[:3]`，把**板块 key 当代码处理**：`'main'` 无数字 → `''`。

于是 `universe: ['main','cyb']` 被归一化成 `['','']`（truthy），过滤时无一命中
→ 报 `无有效得分`。**单板块传字符串正常，多板块传列表必挂**。

修复：板块 key（`main/cyb/kcb/bj`）原样保留，非板块 key 才取前 3 位前缀。

### 3.2 模拟盘持仓被清零（backend，破坏性回写）

`TradingCoordinator.sync_state()` 以「内存券商状态」为准回写 DB：

```python
# 第 ④ 步：无条件用内存 cash 覆盖 DB
await repo.update_account_balances(..., cash=info.cash_balance, ...)
# 第 ⑥ 步：删除 DB 中内存不存在的持仓行
for row in await repo.list_positions(session, mode):
    if (row.symbol, row.side) not in seen:
        await session.delete(row)
```

只要内存是空的/陈旧的，就会把 DB 持仓清空、现金刷回初始值。
**这正是 600036 历史持仓消失的根因**（此前误判为"整表被清空"，实为此路径）。

根因：唯一的保护是 `_restore_broker_state()`，但其门槛是
「`restored` 标志 = 每进程一次」，而 `restored` 挂在 `SimulatedBroker`
（lru_cache 单例）上、真实状态却在 `simulator_service`（模块级单例）里，
两者生命周期会脱节 —— 回灌后若撮合服务单例被重建，`restored` 仍为 True 但内存已空。

修复：
- `SimulatedBroker.restore()` 记录回灌时所基于的 `_svc` 对象
- 新增 `is_restore_valid()` = `restored and _restored_svc is _svc`
- `_restore_broker_state()` 改为「回灌仍有效则跳过」，失效则**重新回灌**
- `sync_state()` 删除循环加闸：内存不可信时**跳过删除并告警**

回归验证：连续 3 次 `sync_state()` 均保持 `600036.SH 1000 股`、现金 959,887.97。

### 3.3 `list_positions` 缺少账户维度（backend）

原实现只按 `mode` 过滤，同 mode 多账户时会在删除环节互相干扰。
修复：新增可选 `account_id` 参数（不传保持原行为以兼容既有调用）。

### 3.4 取价失真（backend）

`huatai_trading.py::get_market_price()` 两阶段问题：

1. 对未内置标的返回 **0.0** → 持仓市值/浮盈归零（显示成「-成本」假亏损）；
   且 `total_assets` 被低估 → 风控单笔/单仓比例上限被压低 → **正常买单被误拒**
   （100 万账户分 5 只、每笔约 19 万即全部遭拒）
2. 改为回落后，仍**优先用写死的演示价表**（600036 表内 45.0 vs 真实 40.86）→ 估值失真

最终修复：**真实行情优先，演示价表仅兜底**
（1. `factor.raw_bars` 最新收盘价 → 2. 演示价表 → 3. 0.0）。

| 标的 | 演示价 | 真实收盘 |
|---|---|---|
| 600036.SH | 45.04 | **40.86** |
| 600519.SH | 1900.00 | **1299.56** |
| 300750.SZ | 240.00 | **358.10** |
| 000651.SZ | 58.00 | **38.55** |
| 000001.SH | 3400.74 | 3400.74（库内无指数数据，正确回落） |

## 五、流程澄清：选股与调仓相互独立

调仓由 backend 调度器驱动，与选股解耦：

```
① 选股   proxy.scores(config) → DC /strategy/scores → compute_target()
         纯计算，无副作用
              ↓ 相互独立
② 调仓   backend/app/tasks/scheduler.py
         CronTrigger(mon-fri, hour='9-15', minute='*/15', tz=Asia/Shanghai)
         → scan_and_rebalance(db, mode)   ← 不带 force
```

三重闸门：`is_rebalance_day()`（`every_n_days:1`）+ `time_reached()`
（策略 `trade_time=14:29`）+ 当日防重 `(strategy_id, rebalance_date, mode)`。

→ **真实下单只发生在 14:29 之后的首个 tick（14:30/14:45/15:00），且取价走
`latest_prices()` → DC `/raw/latest-prices` 实时行情。**

> 踩坑记录：曾以 `force=True` 在 08:39（开盘前）执行，绕过三重闸门，
> 并用非实时价成交，且写入了当日调仓记录 —— 导致 14:30 的合法调仓会被
> 防重逻辑判定「今日已执行」而跳过。已清理该记录与相关订单/成交。
